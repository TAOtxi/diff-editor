# 文件差异对比编辑器

纯前端、纯本地的双文件差异对比与合并工具。文件内容只在浏览器内存中处理，不经过任何服务端。

目标浏览器为 Chrome：直接使用 File System Access API 写回本地文件，不做降级。其他浏览器打开时会显示明确提示。

## 快速开始

包管理器为 pnpm（版本由 `package.json` 的 `packageManager` 字段锁定，`corepack enable` 后会自动切到对应版本）。`preinstall` 钩子会拦截 npm / yarn 安装，避免出现第二份锁文件。

```bash
corepack enable
pnpm install
pnpm dev         # http://localhost:5273
pnpm check       # tsc + eslint + vitest
pnpm build       # 产物在 dist/
```

## 核心模型

对比为两文件对比（2-way）。文本按行切分后跑 Myers 差异算法，合并为四类差异块：

| 类型 | 含义 | 左栏 | 右栏 |
|---|---|---|---|
| `equal` | 相同 | 有 | 有（一致） |
| `delete` | 仅左侧存在 | 有 | 空 |
| `insert` | 仅右侧存在 | 空 | 有 |
| `conflict` | 双边都有且不同 | 有 | 有（不同） |

`conflict` 即「冲突」。`delete` / `insert` 是单边差异，不算冲突。

底层只有四种操作，共同不变式是：**执行后该块左右两侧内容一致，差异总数减一**。

| 操作 | 结果 |
|---|---|
| `takeLeft` | 两侧均采用左侧内容 |
| `takeRight` | 两侧均采用右侧内容 |
| `keepBoth` | 两侧均采用「左 + 右」拼接 |
| `deleteBoth` | 两侧均删除该块 |

单边块上这套语义会呈现为符合直觉的效果，UI 标签随之变化：

- `delete` 块（左有右无）：`takeLeft` 显示为「复制到右侧」，`takeRight` 显示为「删除该差异」
- `insert` 块（左无右有）：`takeRight` 显示为「复制到左侧」，`takeLeft` 显示为「删除该差异」

## 操作方式

载入：点击「打开」选择文件、把文件拖到标题栏、或用「粘贴」直接贴入文本。

差异操作：中缝按钮。`→` `←` 表示内容流向，`⇄` 保留两者，`✕` 两侧都删除。

编辑：双击任意行就地改单行（Enter 提交，Esc 取消）；「编辑」按钮打开整篇编辑。

保存：`Cmd+S` 写回原文件。未绑定文件句柄时用「另存为」。保存会保留原文件的行尾风格、BOM 与末尾换行。

## 快捷键

| 快捷键 | 功能 |
|---|---|
| `Alt+↓` / `Alt+↑` | 下一个 / 上一个差异 |
| `Alt+Home` / `Alt+End` | 首个 / 末个差异 |
| `Cmd+Z` / `Cmd+Shift+Z` | 撤销 / 重做 |
| `Cmd+S` | 保存两侧 |

块级操作与手动输入共用同一条撤销栈，块操作是一个原子步骤。

## 目录结构

```text
src/
├── core/          # 纯函数引擎，无 UI 依赖
│   ├── myers.ts       # Myers 线性空间差异算法
│   ├── diff.ts        # 行级差异 → 差异块
│   ├── inline.ts      # 行内词级差异（仅用于高亮）
│   ├── operations.ts  # 四种块级操作
│   ├── text.ts        # 行切分、EOL、BOM、归一化
│   └── types.ts
├── state/         # reducer 与撤销栈
├── view/rows.ts   # 差异块 → 渲染行（含折叠）
├── worker/        # 差异计算 Worker
├── fs/            # File System Access 封装
├── hooks/         # useDiff（Worker 调度）、useNavigation
└── components/    # UI
```

## 设计取舍

**行是操作的最小单位。** 冲突块内做词级高亮，但不支持单独采用行内片段。这避免了片段级状态管理的复杂度。

**文档是唯一真源。** 差异块只持有行区间下标，不复制行内容，避免两份状态不一致。差异结果不进 reducer，由文档派生。

**撤销栈保存快照而非反向补丁。** 块操作与手动编辑的反向补丁形式不统一，快照实现简单且不易出错。代价是内存，通过 200 步上限与「相邻文本编辑合并」控制。

**两栏共用一个行列表。** 左右天然对齐，不会因行高差异错位，比分别渲染再同步滚动更可靠。

**整篇编辑走对话框。** 虚拟滚动只渲染视口内的行，就地编辑整篇会丢失未渲染部分的编辑状态。

## 正确性验证

差异算法的正确性依赖交叉验证：`myers.test.ts` 用 DP 版 LCS 作参照实现，对约 580 组随机序列断言「编辑脚本的 equal 段总长等于 LCS 长度」，即结果是最优解，同时校验脚本能无损回放出两侧原序列。

块操作的核心不变式（执行后差异数恰好减一）在 `operations.test.ts` 中对四种操作 × 七种场景逐一断言。

```bash
pnpm coverage   # 引擎层覆盖率
```

## 性能

差异计算在 Web Worker 中执行，输入防抖 250ms，渲染用固定行高虚拟滚动。

实测（M 系列 Mac）：

| 规模 | 耗时 |
|---|---|
| 1 万行 / 50 处改动 | 1.6ms |
| 5 万行 / 100 处改动 | 3.8ms |
| 10 万行 / 200 处改动 | 8.6ms |
| 5000 行全部不同（最坏） | 248ms |

超过 5MB 或 10 万行会提示确认后再打开。含 NUL 字节的文件按二进制拦截。
